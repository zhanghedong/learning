# Go 账号与进度服务部署与联调

账号及全部学习模块的进度 API、缓存和自动同步已完成联调，生产根地址为 `https://review.studynote.me`。6 套词卡、古诗文、期中冲刺计划，以及只在网页上的首字母默背和期中知识点，共 10 个模块复用同一版本同步协议。网页（`web/assets/sync.js`）和 App 共用这套账号，网页已不再使用旧 Python 同步码服务。

## 本机运行

要求 Go 1.27+。依赖由 go.mod/go.sum 固定，SQLite 使用纯 Go 驱动。

```bash
cd server
go test -race ./...
go vet ./...
go build -o bin/review-api ./cmd/review-api
export REVIEW_DB="$PWD/data/review.db"
export REVIEW_CODE_SECRET="$(openssl rand -hex 32)"
./bin/review-api
```

地址默认 `127.0.0.1:3108`。固定保存 REVIEW_CODE_SECRET，重启时使用同一个值，否则已发送验证码会失效；已有会话不依赖此密钥。`GET /healthz` 检查数据库连接。

服务默认不配置邮件，因此关闭自助注册、绑定与找回，仅允许已有账号登录。配置 `.env.example` 中的 SMTP STARTTLS 参数后再启动。环境文件不会由二进制自动读取，本机用 shell 导出，systemd 用 EnvironmentFile。只支持要求 TLS 的 SMTP（通常为 587）；不支持隐式 TLS 465。验证码不返回到 API、不写日志。真实收件验收需实际邮箱配置。

## 创建初始账号

家庭成员账号用 `deploy/create-users.sh` 批量创建，首次登录不要求改密：每行一个“手机号 密码”，经 SSH 标准输入传到服务器，不出现在命令行参数里。

```bash
printf '%s %s\n' 13800000000 123456 | bash server/deploy/create-users.sh
```

下面是原来的单个账号方式（默认要求首次登录改密，设 `REVIEW_BOOTSTRAP_MUST_CHANGE=0` 可关闭）：

仅限管理员在服务器上核实邮箱/手机号归属后执行；不提供 HTTP 绕过验证码入口。手机号需国际格式，例如 +86 后接中国号码，不自动猜测国家。

```bash
# 与服务使用同一 REVIEW_DB；不要把真实密码直接写进命令历史。
read -r REVIEW_BOOTSTRAP_IDENTIFIER
export REVIEW_BOOTSTRAP_IDENTIFIER
read -rs REVIEW_BOOTSTRAP_PASSWORD
export REVIEW_BOOTSTRAP_PASSWORD
./bin/review-api create-user
unset REVIEW_BOOTSTRAP_IDENTIFIER REVIEW_BOOTSTRAP_PASSWORD
```

密码至少 6 个字符、最多 256 字节（家庭内部使用，允许 6 位数字）。初始账号可登录和改密，不能绑定邮箱直到改密完成。进度 API 在初始密码未修改时返回 403 password_change_required。

## 客户端联调

生产构建设置 `EXPO_PUBLIC_API_URL=https://你的域名`，也可在账号页连接完整 HTTPS 根地址。不要带 `/api/v1`、查询参数或凭据。token 存入系统安全存储，配置与 token 一起绑定到服务器地址；已登录时不能切换服务器。

本机 iOS 模拟器可临时启用 loopback HTTP：

```bash
cd mobile
REVIEW_ALLOW_LOCAL_API=1 REVIEW_ALLOW_IPHONE=1 \
EXPO_PUBLIC_API_URL=http://127.0.0.1:3108 \
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer \
npx expo run:ios --device --configuration Release --no-bundler
```

此开关仅允许 localhost/loopback HTTP，并为测试构建设置本地网络 ATS 选项，不能用于生产构建。手机中的 localhost 是手机自身；真机联调应使用可达的 HTTPS 测试域名。新增 expo-secure-store 原生依赖后要重新 prebuild/安装 Pods/编译，P0 旧安装包不会自动获得账号页。

账号页支持登录、邮箱验证码注册/找回、改密、退出，以及手机号账号绑定邮箱。没有 SMTP 时不显示注册/找回标签；短信注册和短信找回未实现。离线退出失败会保留登录态，提示重试，不显示已撤销；401 则清除过期凭据。登录重启会向服务器重新验证，网络失败保留凭据但显示待联网验证。

## API 约定

请求/响应为 JSON，认证通过 `Authorization: Bearer TOKEN`。会话 30 天固定到期；退出撤销当前会话，改密/重置撤销该账号全部会话。不返回密码散列。请求上限 256 KiB，密码运算并发上限 4。限流使用内存，重启会重置；当前不信任转发 IP 头，经反向代理时 Go 限流按代理连接地址汇总，适合小系统，扩大使用前应增加可信代理和边缘限流。

| 请求 | 字段/返回 |
| --- | --- |
| GET /api/v1/auth/capabilities | emailRegistration、emailRecovery、phoneRegistration |
| POST /api/v1/auth/challenges | identifier、purpose（register/reset/bind）；返回 challengeId；bind 需要登录 |
| POST /api/v1/auth/register | identifier、password、challengeId、code；成功后另行登录 |
| POST /api/v1/auth/login | identifier、password；返回 token、expiresAt（Unix 秒）、user |
| GET /api/v1/me | 当前账号，忽略请求中的 userId，不允许指定其他账号 |
| POST /api/v1/auth/logout | 空对象；撤销当前会话 |
| POST /api/v1/auth/change-password | oldPassword、password |
| POST /api/v1/auth/reset-password | identifier、password、challengeId、code |
| POST /api/v1/me/identities | identifier、challengeId、code；仅支持补绑邮箱，不替换已有邮箱 |

邮箱登录标识统一转小写，首期只接受 ASCII 邮箱；手机号接受带 + 的 8–15 位国际格式；11 位中国大陆手机号可不写区号，统一存为 +86 开头。验证码按用户、标识和用途绑定，10 分钟有效、最多 5 次尝试；发送同标识每分钟一次。统一错误格式 `{error:{code,message}}`。

## Linux 部署

1. 按目标服务器架构构建，例如 `CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -o bin/review-api ./cmd/review-api`。正式服务器架构需核实。
2. 创建专用系统用户 review-api，二进制放 `/opt/review-api/review-api`，配置放 `/etc/review-api.env`（root:review-api，0640）。数据库位于 `/var/lib/review-api/review.db`，不得覆盖旧 Python 数据库。
3. 安装 `deploy/review-api.service`，启动前检查数据库路径和配置；StateDirectory 自动建立持久目录。反向代理参考 `deploy/nginx.conf.example`，置于已有合法证书的 HTTPS server 配置中。
4. 新服务使用 3108 和 `/api/v1/`；旧 3107 和 `/api/sync/` 保持原路由。`/api/v1/` 路由同时写在仓库的 `deploy/nginx/review.studynote.me.conf`，因为根目录的 `deploy-review.sh` 每次发布网页都会用它整体覆盖服务器上的 nginx 配置。
5. 使用独立测试账号验证登录、退出、改密以及服务器重启后持久化，再开放客户端使用。

当前已在原服务器同机上线。可从仓库根目录执行 `bash server/deploy/deploy.sh`：先测试、vet 和 Linux amd64 构建，再上传并安装。可用 REVIEW_DEPLOY_SERVER、REVIEW_DEPLOY_IDENTITY 覆盖目标和 SSH key；默认目标仅适用于本项目现有服务器，换环境先核对。

安装脚本保留旧二进制及 nginx 配置到 `/opt/review-api/releases/`；更新前执行一致性备份。它只增加 `/api/v1/` 路由，不发布网页静态文件。API 健康失败会尝试恢复旧二进制；nginx 校验失败会恢复其配置。自动恢复二进制不能回退数据库结构。

检查：`systemctl is-active review-api nginx review-sync review-api-backup.timer`、`curl -f http://127.0.0.1:3108/healthz`，以及外网 `/api/v1/auth/capabilities`。不带认证的 `/api/v1/progress` 应返回 401，旧首页及 `/api/sync/` 路由仍应可用。真实邮件收件仍需另配 SMTP。

## 备份与恢复

数据库内含密码散列、会话散列和验证码 HMAC，应限制访问。生产已启用 `review-api-backup.timer`，每天 03:15（服务器时区）运行、随机延迟最多 5 分钟，补跑错过的任务。快照在 `/var/backups/review-api`，目录 0700、文件 0600，成功生成新快照后清理超过 30 天的旧快照。

```bash
# 在服务器立即生成一次快照，不必停止服务
systemctl start review-api-backup.service
systemctl status review-api-backup.service --no-pager
systemctl list-timers review-api-backup.timer
```

备份命令为 `review-api backup /绝对路径/新文件.db`，使用与服务一致的 REVIEW_DB 环境，目标不可已存在。通过 SQLite VACUUM INTO 生成一致性快照，不直接复制运行中的主 db 文件；已提交 WAL 数据包括在内。环境文件不会由 CLI 自动读取。

本次已将一致性快照下载到 Mac 的 `~/Library/Application Support/Review/backups/server/`，完整性通过；每日自动备份目前仍在同一台服务器，持续自动异地复制尚未配置。

恢复或数据库回退必须维护窗口执行：

1. 先生成当前库备份并保存到独立位置，检查待恢复快照 `PRAGMA integrity_check` 为 ok。不要直接改唯一备份。
2. `systemctl stop review-api`，确认无其他进程访问该库。保留当前 db、wal、shm 整套文件用于应急。
3. 将快照复制为新的恢复工作文件。在工作文件中执行 `DELETE FROM sessions; DELETE FROM verification_challenges;`，避免旧会话或已消费验证码复活；不会删除账号及学习记录。
4. 用工作文件替换 `/var/lib/review-api/review.db`，仅在确认服务停止后移走旧的同名 `-wal`、`-shm`，不要让旧 WAL 与新库混用。设置 owner 为 review-api:review-api、权限 0600。
5. 启动服务，检查 healthz、结构版本，使用正式用户重新登录验证数据。客户端遇到版本倒退会显式报错，不静默覆盖；先核对当前库和备份，导出保留本机离线数据，再选择需要恢复的版本。

回退程序时先停止服务，从 `/opt/review-api/releases/` 选择对应旧程序。核对该版本支持的 schema；必要时按上述步骤恢复匹配的数据库。旧版本不能读取更新结构时应停止回退，不能删除迁移记录来绕过保护。nginx 配置也需 `nginx -t` 后再 reload。

首次启动自动执行事务迁移，检测到较新结构会拒绝启动。发布前做一致性备份；回退二进制不代表结构自动回退。当前迁移为独立数据库 v2（v1 账号、v2 进度/备份/幂等记录），可从 v1 自动升级，不改旧同步码表。

实现依据：[Go Argon2](https://pkg.go.dev/golang.org/x/crypto/argon2)、[SQLite Go 驱动](https://pkg.go.dev/modernc.org/sqlite)、[Expo SecureStore](https://docs.expo.dev/versions/latest/sdk/securestore/)。

## 进度 API

所有接口要求 Bearer 会话，身份只取自会话。query 中的 deckKey 需 URL 编码。允许以下模块：

- `textbooks/minjiao/english/grade3b-words`
- `textbooks/minjiao/english/grade4a-words`
- `textbooks/renai/english/grade7b-words`
- `textbooks/renai/english/grade8s-words`
- `textbooks/pep/chinese/grade7b-characters`
- `other/en20260704`
- `textbooks/pep/chinese/grade8a-required-recitations`
- `other/midterm-plan-2026`
- `textbooks/pep/chinese/grade8a-midterm-firstletter`（网页自管结构，服务端只要求 JSON 对象）
- `textbooks/pep/chinese/grade8a-midterm-qa`（同上）

请求上限 256 KiB，初始账号先改密。

| 方法 | 结果 |
| --- | --- |
| GET /api/v1/progress | 当前账号教材进度摘要 |
| GET /api/v1/progress?deckKey=… | `{deckKey,revision,schemaVersion,payload,updatedAt}`；不存在时 revision=0、payload=null、updatedAt 空字符串 |
| PUT /api/v1/progress?deckKey=… | 条件更新并返回完整新快照 |
| GET /api/v1/progress/backups?deckKey=… | 当前账号该教材最近 10 个被覆盖快照 |
| GET /api/v1/progress/backups/{id} | 本人指定备份；恢复时再次 PUT 并检查版本 |

PUT 示例（mutationId 使用随机唯一值，同一次重试复用整个请求）：

```json
{
  "baseRevision": 0,
  "mutationId": "a34f0805bb7d44f28ca0b5eea7ecbd92",
  "schemaVersion": 1,
  "payload": {
    "status": {"0|单词|kill": "got"},
    "pref": {"unit": 0, "lesson": -1, "dir": 0, "peekAll": false, "sound": true, "lastKey": "0|单词|put", "lastIdx": 1}
  },
  "reason": "update"
}
```

状态仅允许 got/review，未学条目省略。reason 允许 update/import/reset/restore/conflict/guest。服务端校验教材条目与偏好范围，不接受任意业务字段。

baseRevision 过期返回 HTTP 409：`{error:{code:"revision_conflict",message},current:完整快照}`。相同 mutationId 与规范化后相同请求返回原成功结果；同 id 更改请求返回 409 mutation_reused。版本递增、覆盖前备份和幂等结果在一个事务中写入；首期幂等记录不自动清理。恢复旧数据库后若服务端版本倒退，客户端拒绝静默拉取覆盖，需先排查恢复状态。

古诗文 payload 为 `{version:1,items:{},pieces:{},pref:{view:"overview",pieceId:null},roundCounter:0}`；view 只允许 overview/learn/review/full。items 使用生成内容中的重点词/背诵段 ID，记录 stage、correct、wrong、lastCorrectRound、lastSelf；pieces 按篇目 ID 记录 started、learned、step。

期中计划 payload 为 `{version:1,checks:{"t-2026-10-26-0":true}}`。仅接受 104 个已知任务 ID 和布尔值，false 规范化为省略；不接受任意日期任务、文本或无效勾选。沿用网页 ID，新增导出文件无需把浏览器本地数据改成账号凭据。两个模块都沿用 schemaVersion=1、CAS 版本检查和幂等重试，不需新增数据库结构迁移。
